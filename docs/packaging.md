# Packaging as a Home Assistant add-on

The repository root is a Home Assistant add-on repository (`repository.yaml`); the add-on lives in `ha_climate/`.

## Image layout

Built by `ha_climate/Dockerfile` with the **repository root as build context** (it needs `app/` and `frontend/`):

1. `frontend` stage: `node:22.12.0-alpine` on `$BUILDPLATFORM`, `npm ci && npm run build`.
2. `vendor` stage: `php:8.4-cli-alpine`, `composer install --no-dev`, then a classmap-authoritative autoloader.
3. Runtime stage: `ARG BUILD_FROM` (Home Assistant base image, Alpine 3.24, pinned in `build.yaml`) with
   Alpine's `php84*` packages, `nginx`, an unprivileged `app` user.

| Path in the image             | Content                                              |
| ----------------------------- | ---------------------------------------------------- |
| `/opt/ha-climate/app`         | Symfony app (prod vendor, warmed `var/cache/prod`)   |
| `/opt/ha-climate/frontend`    | built SPA, served by nginx                           |
| `/data`                       | persistent volume: `app.db`, `app_secret`, `engine.token` |

## Services (s6-overlay v3, `ha_climate/rootfs/etc/s6-overlay/s6-rc.d/`)

| Service    | Type    | Role                                                                                      |
| ---------- | ------- | ----------------------------------------------------------------------------------------- |
| `init-app` | oneshot | reads `log_level`, creates `/data/app_secret` and `/data/engine.token` (0600) once, migrations, `app:seed-defaults`, cache warm-up |
| `php-fpm`  | longrun | unix socket `/run/php/php-fpm.sock`, ondemand, max 4 workers, runs as `app`               |
| `nginx`    | longrun | port 8099; `/api/live` proxied to the engine (no buffering), `/api/` to PHP-FPM, SPA otherwise |
| `engine`   | longrun | `bin/console app:engine:run` as `app`; s6 restarts it when it exits                       |

`php-fpm`, `nginx` and `engine` depend on `init-app`. Logs of all services go to stdout/stderr.

## Environment

Fixed in the Dockerfile: `APP_ENV=prod`, `APP_DEBUG=0`, `DATABASE_URL=sqlite:////data/app.db`,
`ENGINE_TOKEN_FILE=/data/engine.token`, `ENGINE_PORT=8100`, `SYMFONY_TRUSTED_PROXIES=172.30.32.2`.
`APP_SECRET` is generated by `init-app` and exported through `/run/s6/container_environment` (use
`/command/with-contenv` in `docker exec` shells). `SUPERVISOR_TOKEN` is provided by the Supervisor.

Standalone/development only: `HA_URL` + `HA_TOKEN` (instead of `SUPERVISOR_TOKEN`),
`HA_CLIMATE_LOG_LEVEL` (when there is no `/data/options.json`) and `HA_CLIMATE_DEV_ALLOW_ALL=1`, which lifts the
nginx restriction to the Supervisor ingress proxy (`172.30.32.2`) and loopback. Never set it in production.

The `log_level` option is turned into `app/config/packages/prod/monolog_level.yaml` by `init-app` (the cache is
rebuilt when it changes).

## Build and test locally

```bash
docker run --rm -i hadolint/hadolint < ha_climate/Dockerfile
docker build -f ha_climate/Dockerfile \
  --build-arg BUILD_FROM=ghcr.io/home-assistant/amd64-base:3.24-2026.10.1 -t ha-climate:dev .

docker/dev/bootstrap-ha.sh                 # dev Home Assistant + token in docker/dev/.env.dev
ha_climate/assets-src/run-standalone.sh    # runs the image on http://localhost:8099, data in .cache/addon-data
curl localhost:8099/api/health
curl localhost:8099/api/context            # engine.connected must be true
curl -N localhost:8099/api/live            # SSE stream
docker compose -f compose.dev.yaml down
```

`ha_climate/assets-src/build-icons.sh` regenerates `icon.png` / `logo.png` from the SVG sources.

The Supervisor cannot build this image from a repository (its build context is `ha_climate/`): releases publish a
prebuilt image and add the `image:` key to `config.yaml`.
